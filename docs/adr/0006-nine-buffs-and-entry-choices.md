# ADR 0006：九增益与进关选择（AC-04 / AC-08）

日期：2026-10-27。状态：本 PR 实现方案，效果数值为可调试玩默认。

## 来源与边界

用户要求把已完成的九增益改进上传团队仓库，对应 Issue #11（AC-04）和 #15（AC-08）。原改进在独立的两关副本；本 PR 从团队 `main` 的 `70aa9d6` 接入所需增益能力，不用独立副本覆盖主分支的关卡、Boss、fixture 或引擎配置。

沿用用户已选择的枪械、刀具、技能三派，分别为 `firearm`、`blade`、`skill`。这与历史文档的狂战士、军火大亨、鹰眼占位方案不同；历史设计文件和旧证明保留。当前可玩卡片与临时数值以 [九增益说明](../Buff当前实现.md) 为准，是否成为团队最终设计由 PR 审查决定。

## 选择流程

> 下面这一段的五次流程已被文末「修订（2026-10-27，#22）」取代。现行规则以该节为准。

保留团队的小关 1、小关 2、Boss 三张地图，不改地图文件或生成器。一局获胜必须经过五次独立选择：

`0:enter → 0:clear → 1:enter → 1:clear → 2:enter → Boss 胜利`

入场界面暂停战斗，选卡生效后才把玩家目标交给敌人。小关清守卫后才能砸点，插旗升起后给一次通关选择；选完才载入下一关，下一关另有自己的入场选择。Boss 入场也选一次，但保留原 `open_at_start`：核心开放与守卫是否清零无关。Boss 完成后直接结算，没有第六次选卡。

`RunState.selection_history` 记录关卡、`enter` / `clear`、卡片 id 与名称；死亡、新局或 fixture 重开时清空。选择界面锁定一次提交，控制器也防止重复发牌、重复推进和阵亡后的迟到占点回调。

## 卡池与叠加

每派三张，每次各给一张，因此可以连续专精或混搭。首轮固定给危险弹匣、子弹收藏家、反击护盾；之后两轮展示每派另外两张，前三轮即可看到全部九张。每派用完后重新洗牌，可以再次选择并叠加。

卡片只修改 `Stats`，算法为 `(base + Σadd) × Πmul`，能力组件读取数值执行效果。卡片、HUD 和选择界面用稳定 id 计算层数。技能三卡都解锁同一个 G 护盾；未选技能卡不能使用护盾。

发牌使用战区已播种的全局随机数；新局和 fixture 重开重置发牌袋。保留 `RunState.run_seed`、`zone_seed()`、`SimClock`、固定步长与同步导航规则，不引入玩法侧 `randomize()` 或独立 RNG。旧 fixture 资源可以继续携带旧通用卡。

## 战斗与后续集成

保留用户已有的空仓弹匣爆炸、V 挥刀弹反收藏、紫盾挡伤后反击。效果、边界和默认值见九增益说明。本分支已变基到包含 #20 的 `main`：三把枪和三把近战留在玩家身上，Q 继续切近战，紫色护盾改到 G。F 仍是 `interact`，目前没有玩法读取，所以没有占用 F。

未带入城市素材版的布景、手雷、可破坏箱墙或补给，也未实现未来候选卡、融合、分支或新关卡。原独立两关工程保持原样。

## 修订（2026-10-27，#22）

Kyrie 在 issue #22 把一局选择从 5 次改为 3 次：`0:enter → 0:clear → 1:clear → Boss 胜利`。只在一局第一关开打前选一次，两个小关结束各选一次。小关 2 和 Boss 进场直接开打，不弹选择；Boss 后不选。普通局死亡或胜利后重开回到小关 1，会再弹一次开局选择。fixture 若不是从第一关起步（FX-002 从 Boss 关起步）则进场不选。

这与 #11 AC-04 的原意一致：进关前 1 次、小关后 1 次，三次时机。上文「五次独立选择」以及 `1:enter`、`2:enter` 的流程已被本修订取代，保留原文是为了不抹掉当时的实现记录。

直接开打的关要自己 `get_tree().paused = false`。通关选择会把树暂停，原先靠下一关的入场界面关闭时解除；去掉那次入场后，不解除就会一直停着。`seed()` 和 `SimClock.restart()` 仍在 `ZoneDirector._ready` 开头，不引入墙钟或新的随机数。
