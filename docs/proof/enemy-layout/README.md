# Issue #42 Proof：首波守卫分布在整个战场

#42 之前，小关的守卫都围在据点楼（z≈-8）旁边，Boss 关的 6 名小兵挤在 Boss 周围的 4 米环上，而且全部面向出生点（yaw 180）。现在守卫按战场纵深分成前、中、后三段，Boss 关只留 2 名贴身护卫，其余 4 名分散到前中两段。规则和数值写在 [ADR 0004](../../adr/0004-boss-wave-and-core.md) 和 [ADR 0007](../../adr/0007-reinforcements-shockwave-pedestal.md) 的 #42 修订里；站位由 [tools/gen_zones.py](../../../tools/gen_zones.py) 生成，不用随机数。

三张图由 [tests/enemy_layout_proof.gd](../../../tests/enemy_layout_proof.gd) 在真实窗口里拍（不能 `--headless`），2026-10-28，Godot 4.7.2：

```bash
G=/mnt/d/Godot/Godot_v4.7.2-stable_win64_console.exe
P="$(wslpath -w "$PWD")"
"$G" --path "$P" res://tests/enemy_layout_proof.tscn -- --out=<windows path>
```

默认输出到 `docs/proof/enemy-layout/`。脚本把每名敌人在第一个物理 tick 之前冻结，所以拍到的是场景里写死的站位，不是 AI 走位之后的样子。

## 数值检查

截图只证明“看起来分开了”，硬性条件由 [tests/enemy_layout_test.gd](../../../tests/enemy_layout_test.gd) 逐张地图检查，`ALL PASSED (34 checks, 0 failed)`：

- 数量不变：zone_1 4、zone_2 6、boss 6+1；三段人数分别是 1/1/2、2/2/2、2/2/2；
- 所有敌人离出生点至少 15 m：最近分别是 15.12、15.21、15.56 m；
- 待机时出生点不在任何敌人的视线里：在 120° 视野锥外，或被 WORLD 挡住（Boss 面向出生点，但 45.02 m 刚好超过 45 m 的 `sight_range`，且中路的 2.5 m 高 `Cover3` 也在射线上）；
- 都站在烘焙导航网格上（最差 0.00 m），没有卡进几何体；
- 任意两名敌人至少相隔 3 m：最近一对分别是 7.91、6.41、4.95 m；
- 非护卫守卫都在掩体点 3.5 m 内；
- Boss 关恰好 2 名护卫在 2–6 m，其余 4 名都比 Boss 更靠近玩家，且都在核心前。

## 局限

- 俯视截图只能看开局站位，不能看交火中怎么换位；站位会在 AI 开始行动后变化。
- “最近掩体点”量的是 `CoverPoints` 标记，不是箱子表面；实际贴掩体的距离比表里的数字大一点。
- 截图时玩家和敌人都是冻结的，HUD 和玩家手上的枪都隐藏了，所以图里没有血量、准星或枪口方向。
- 和 #14 的 fixture 一样，只证明本机、Godot 4.7.2 下这套固定站位；换布局要同时更新生成器和布局测试。
