# Issue #10 Proof（AC-02）

Boss 关：1 个大敌人（Boss）加周围 6 个小敌人，城市核心开局就能砸，占满胜利，阵亡失败。规则和临时数值见 `docs/adr/0004-boss-wave-and-core.md`。

占点配置路径：`zone/capture_config.tres`（窗口 ±150ms、普通 +8%、完美 ×1.5），核心和小关据点用同一份。

由 `tests/boss_proof.tscn` 在真实窗口里先跑一局胜利、再跑一局失败，不是手动录屏：

```bash
godot --path . res://tests/boss_proof.tscn -- --out=<输出目录>
```

另有无界面检查 `tests/boss_test.tscn`（`godot --headless --path . res://tests/boss_test.tscn`），逐条断言波次、开局开放、清场不影响核心、胜利、失败。

## 局限

- **胜利局里敌人被冻结**（`process_mode` 禁用），否则脚本控制的玩家会在砸完前死掉。所以它证明的是“核心不需要清敌人也能砸、占满就胜”，不是“能在交火中砸完”。
- 胜利局的挥锤是脚本按下 `hammer` 动作（真实输入路径），按命中时刻对齐，所以 9 次全是完美打击。
- **失败局是真实 AI**：玩家站着不动，7 个敌人自己开火，没有脚本伤害。本次 1.9 秒死亡，之前几次在 1.7–2.6 秒之间。这说明失败可达，同时说明站着不动活不过两三秒，Boss 关强度待试玩确认（见 `TODO.md`）。
- 没有测“玩家在交火中真的占下核心”。这要有人实机玩一遍。
- Boss、核心、旗都是灰盒占位模型，Boss 没有血条。
- 截图为 128 色 PNG（压缩过，天空渐变处可能有轻微色带）。`run.log` 里的截图路径已从临时目录改成仓库内相对路径，其余未改。
