# 近战证明（AC-05）

AC-05 要求「枪 ×3、近战 ×3、自身护盾都能用，剪影可读」。这一份只覆盖三把近战：匕首、斧、太刀。

由 `tests/melee_proof.tscn` 在真实窗口里跑出，不是手动录屏：

```bash
godot --path . res://tests/melee_proof.tscn -- --out=docs/proof/melee
```

挥砍按 0.08 倍速慢放再截图：读回一帧加 PNG 编码比整个生效窗口还长，正常速度下相机来不及拍到。

轨迹不是看出来的：`MeleeWeapon.tip_screen_position()` 把刀尖投影回屏幕，归一化坐标（-1..1，+y 向上）写在 `run.log` 里；`MeleeWeapon.tip_depth()` 再给出刀尖在眼睛前方多少米。匕首 (-1.00,-0.98) → (1.00,0.98)，斧 (0,0.79) → (0,-0.95)，太刀 (-0.95,0.92) → (0.95,-0.92)。截图只是复核。

深度这一列是补上去的：屏幕坐标对「刀尖在相机后面」和「刀尖在画面里」给出同一个数（投影会翻到另一边），所以只看画面会通过一把整个被裁掉的刀。第一版匕首起手就是这样——刀尖解到了眼睛后面 0.11 米，画面上只剩一小块柄。现在 `_tip_direction()` 把刀尖夹在眼前至少 `MIN_TIP_DEPTH`（0.28 米），测试同时检查两个端点都在这条线之外。

刃口不是靠调角度调出来的：刀尖瞄准只定住两个自由度，剩下的「绕刀轴转多少」有两个互相冲突的要求——刀面朝镜头（剪影宽，但刀尖指着眼睛时没有意义），和刃口朝着挥砍方向（才叫砍，但刀沿着自己走的时候没有意义）。`MeleeWeapon._roll_for()` 两个都算，**挥砍方向真的横过刀刃时（`across` 大于 0.5）直接用刃口领先，只有刀沿着自己走的时候才退回「刀面朝镜头」**。第一版是把两个按各自成立程度对半混，中段会剩一点刀背在前——正好是看得出来的那一段。

刃在模型哪一侧由 `MeleeData.edge_side` 说明。这一项**不能靠肉眼在小图里猜**，也不能靠导出的几何：这把弯刀的顶点太少，轴线的漂移只有几毫米，`bulge` 判据根本读不出凸面。判据是「贴图上画亮的那条线在哪一侧」——把模型摆平、两个面各拍一张（`+Y` 在画面左 / 右各一张），亮边在 `+Y` 那一侧，所以 `+1`。测试里的「刃口领先」不管写反没有都读正数（它会反过来选滚轴），只有这张对照图和实际手感能抓错，这一点第一版就翻过车。

斧是对称的双刃，没有「哪一边是刃」，但它有「哪一面对着地面」的问题：**竖着往下劈时，斧头的板面应该落在挥砍自己的竖直平面里，从眼睛看过去接近侧对镜头——斧刃先着地**。板面正对镜头（`*_roll = 0`）同一个动作就变成拿斧子的平面往下拍，被试玩否掉了。所以斧的 `*_roll` 写 **75°**（离纯侧对差 15°，留一点斧头的体量在画面里），两只手写在中线附近（`cut_*_hand` 的 x 是 0.05 米），幅度是刀尖 (0,0.79) → (0,-0.95)。测试查的是 `blade_facing()` < 0.45，即「不是平板朝镜头」。

代价写在这里：斧头在侧对角度下只有 11 厘米厚，劈到中后段（1.3~1.4 米）看着偏细。这是这台双刃斧的几何决定的——两个斧刃始终垂直于斧柄，斧柄竖直时它们只能左右展开，所以「斧刃朝下」的第一人称表现必然是侧对镜头。想要更厚重的竖劈，得换成单刃斧的模型。

`windup` 和 `strike` 两帧是按事件抓的：起手帧在 `windup` 快走完时，落点那一帧等 `MeleeWeapon.strike_finished`（生效窗口关闭、刃正好到最远点）再拍。用固定延迟会拍在半途——姿势由相位计时器驱动，跟判定同一个时钟。

三把的数值都写在 `weapons/melee/*.tres` 里，是试玩默认值，不是锁定设计（`docs/bible/03_rules.md` 里枪械和近战数值仍标 Design-TBD）。自动化检查是 `tests/melee_test.tscn`，它同时验证这三条轨迹、刀尖深度、刀面朝向（斧也查）、刃口是否领先，以及「吸附」：三把在敌人靠近时都会朝敌人冲一段（匕首 0.35 / 斧 0.45 / 太刀 0.55 米），命中弧线也会转到敌人身上——测试里有一个 43° 偏角的敌人，匕首的 70° 弧本来打不到，靠弧心吸附才劈中。

## 局限

- 截图里没有敌人：守卫先被移除了，否则近战距离内只看得见敌人，看不见武器。
- 这是静止的姿势帧，不是连续的挥击视频。手感仍需要人玩一遍。
- 静止握姿不在截图里：武器只在挥砍时出现，静止时收在下缘之外，拍出来是空屏。
- 斧劈到最底下那一帧，斧头已经出画面下缘，只剩截面（筒口）贴着边；这是「幅度跨过整个画面」的必然结果，不是贴图错。
- 斧头侧对镜头时只有 11 厘米厚，中后段看着偏细（见上）。
- 太刀收招那几帧刃几乎侧对镜头（0.09），因为「刃口领先」优先——这一条是试玩要求，宁可失一点剪影也不拿刀背砍。
- 第一人称模型没有手。斧柄在握点之后被 `tools/export_melee_models.py` 切掉了，所以画面上看到的是柄的截面，不是断模。
- 枪支和护盾的剪影不在这份证明里，AC-05 还没整条通过。
