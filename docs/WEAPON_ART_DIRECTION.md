> 适用范围：玩家第一人称武器（枪械 / 近战），之后可扩展到敌人和环境。

## 1. 核心设计判断

**精神世界可以使用现实世界中熟悉的攻击方式，但不应直接搬入现实军械的视觉语言。**

FPS 中的「连续射击、精准瞄准、近距爆发、重击、快速斩击」仍然直观、好玩。我们要保留这些**交互范式**和现有系统的可复用价值，而不是执着于还原 AK、狙击步枪或某一时代的刀剑。

> **保留功能轮廓，剥离现实细节。让武器像精神世界中的几何构造体，而不是写实物品。**

**已明确的偏好**：简单、抽象、白模感、干净的线条。  
**尚未确定**：精确色板、轮廓线实现方式、发光特效、是否由 Pride 创造武器的世界观解释。

## 2. 统一视觉语言

| 维度 | 推荐做法 | 尽量避免 |
| --- | --- | --- |
| 形体 | 大型简洁几何面、清楚的主轮廓、少量切角和留白 | 螺丝、导轨、扳机机构等写实细件堆叠 |
| 材质 | 以白色 / 浅灰色哑光主体为基调，通过明暗识别形体 | 木纹枪托、逼真金属磨损、迷彩及枪械贴图 |
| 线条 | 用少量深色轮廓线、断线、嵌入线或空心结构强调形态 | 每个三角面都显示线框；密集、闪烁的细线 |
| 点缀 | 如有需要，少量单色光线或悬浮几何片作视觉焦点 | 全身霓虹、过多粒子导致轮廓不清 |
| 动态 | 简洁的后坐、蓄力、拉伸、分离 / 重组等抽象运动 | 为了模拟真实机械而追加大量复杂动画 |

**视觉层级：轮廓 > 大块面的明暗 > 少量线条 > 微小细节。**

「白模」是**艺术选择**，不是尚未完成的灰盒；即使不用复杂贴图，也应认真设计剪影、受光、对比、动画和命中反馈。

## 3. 六种武器：保留战斗身份，不保留真实型号

下面是**外形探索提示**，并非六份必须制作的新资产订单。

| 原有战斗角色 | 抽象化方向 |
| --- | --- |
| 突击步枪（连续输出） | 一条稳定、厚实的长形主体；平行刻线暗示连续脉冲，不需 AK 式机匣和木质枪托 |
| 霰弹枪（近距离爆发） | 短而宽的前端、显著的楔形 / 扇形开口；凭轮廓传达近距离扩散 |
| 狙击枪（远距离精确） | 狭长、近乎一笔延伸的主体；极简同心圆或几何框表示聚焦 / 瞄准 |
| 匕首（快速近战） | 单纯的短三角切面；突显轻巧、锋利和短促动作 |
| 战斧（重击） | 一个突出的不对称楔形头部；突出重量与挥击弧线，而非写实锻造纹理 |
| 太刀（流畅斩击） | 连续而克制的长弧形刃面；用运动轨迹凸显其与斧头、匕首的差异 |

共用一套材质、线条粗细、发光逻辑和几何语言，使它们看起来**属于同一个精神世界**。不同武器必须首先在**剪影、长度、握持姿势与攻击反馈**上区分，不能只靠颜色。

## 4. 第一人称可读性优先

武器既是艺术对象，也是长期占据屏幕的操作界面。

- **一眼识别**：战斗中无需细看，玩家也应能认出拿的是哪一类武器。
- **看得清目标**：白色武器在白色场景中也要有足够明暗对比；第一人称模型不能遮挡重要敌人、准星和攻击提示。
- **动作反馈明确**：射击、命中、换弹 / 冷却、蓄力及近战命中要有清楚的声画反馈，不能因“极简”而失去手感。
- **线条稳定**：密集细线在移动镜头时可能闪烁、产生锯齿；优先粗细可控的局部线条，而非全模型三角网格线框。
- **瞄准可靠**：尤其是狙击枪，抽象外观不应破坏开镜、视野遮挡和准星的一致性。

## 5. 与 Pride / 世界观的联系

**候选解释，尚未定案**：武器是玩家在精神世界中熟悉的攻击概念的投影；或由头顶的皇冠 Pride 将「清除缺陷」的意志塑造成几何武器。

这可以解释为何精神世界允许使用枪械、刀剑，却不需要木头、真实金属与具体枪械型号。**先验证美术和手感，再决定是否把这个解释写入正史。**

## 6. 最小验证实验

**只挑一把现有步枪**，不先重做完整武器库：

1. **保留**现有射击逻辑、命中判定、伤害与输入；只替换第一人称外观及必要的动画表现。
2. 在 Godot 中以基础几何体 / 简单网格快速做一版**浅色主体 + 清晰大轮廓 + 少量线条**；暂不投入复杂 Shader 或贴图。
3. 在**白色场景和深色场景**分别实测：第一人称持枪、移动射击、瞄准、枪口火光与命中反馈。
4. 同时展示「现有写实倾向 Low-poly 枪」与「新抽象枪」的同视角画面，让三名队员及少量试玩者判断：
   - 它是否属于这个精神世界？
   - 是否依然像一把能用、好用的枪？
   - 战斗中是否容易识别、瞄准和读取命中反馈？
5. 原型成立后，才建立统一材质 / 线条组件，扩展至狙击、霰弹、刀剑。

**本文件不要求重写 FPS 系统，也不决定具体实现方案。** 如果纯白模在浅色环境下可读性差，可以调整灰阶、边线、负空间或局部强调色，而不是为了坚持某种风格牺牲操作体验。
