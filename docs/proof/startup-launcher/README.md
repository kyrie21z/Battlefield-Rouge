# Windows 更新后启动黑屏

日期：2026-11-11。基线：main `84601d3ca7dd6e695693a28ac31b46975b1e075c`。

## 原因与修复

用户反馈新版启动后停在黑屏或 Godot 标志。实际主游戏目录的全局类索引和 UID 缓存仍为 2026-11-04，源码已包含新开场、四领域及局外成长。旧本地启动器直接运行游戏，没有先执行编辑器资源准备。

同一路径原生启动复现了 `CrownVoiceDSP`、`CrownModel`、`MetaProgressionStore`、`CrownForge` 等类找不到以及 `ui/game_start.gd` 加载失败。另用无 `.godot` 的旧整合版本源码副本复现了相同类别的脚本类型/导入贴图缺失。引擎即使场景脚本失败也可能退出 0，单看进程退出码不能确认启动成功。

新增可随源码分发的根启动器及 `tools/launch_game.cmd`：每次先用同一引擎执行 `--headless --editor --import`，等待资源与全局类准备完成，再启动原项目入口。准备阶段显示文字；非零退出、脚本/资源导入失败或缺失类索引会阻止运行并显示日志路径。日志写入 `.runtime/startup-prepare.log`、`startup-import.log` 和 `game.log`。引擎默认位置按启动器所在磁盘解析 `godot/Godot_v4.7.2-stable_win64.exe`，允许 `GODOT_EXE` 覆盖。

启动器保持传入参数和外部工作目录无关，准备完成后独立打开游戏窗口。保留继承的 APPDATA，不切换用户档案，不删除素材缓存或存档。没有改游戏规则、场景、开场计时或战斗代码。

## 实际验证

Godot 4.7.2 / Windows / Forward+ / Vulkan / RTX 4060 Laptop：

- 最新 main 的旧缓存目录：先复现脚本加载失败，再用修复后的同一本地“启动游戏.cmd”准备资源；首次增量准备 37.781 秒。新 worktree 从无 `.godot` 状态完成首次导入，准备 31.250 秒。时间仅为本机观察。
- 主游戏启动器从项目以外的带空格目录调用，原生 `opening_boot_test` 的跳过路线 **14/14** 通过：真实新开场、开门、局外锻造台交接、唯一实际领域、初始赐福、手枪开火、死亡与重开、两个旧 fixture 入口。重复准备 8.718 秒，含验证流程总计 19.703 秒。
- 修复分支根启动器的完整演出路线同样 **14/14**，重复准备 8.703 秒，含验证流程总计 20.125 秒。两条路线实际渲染截图已在本机查看，确认新开场和实际战斗画面均出现；不新增或替换游戏美术。
- `opening_sequence_test` **16/16** 通过，包含正常演出、同一真实相机、物理行走过门、暂停与减少镜头移动。
- 独立损坏资源工程确实被启动器阻止：退出 1、显示资源准备失败，没有进入“Opening Mind Freak”步骤。无效引擎路径在导入前退出 1。
- 原生测试使用独立测试档案环境，未操作正式钱包或存档。未改玩法，未重跑全部游戏回归、帧时基准和其他平台。

本机受限运行环境的默认编辑器配置目录存在 Safe save / feature_profiles / editor settings 保存诊断；测试用独立 APPDATA 可完成准备。保留诊断，不更改系统权限、证书或编辑器安全保存设置。原生两条成功路线及开场检查无脚本/资源加载错误。
