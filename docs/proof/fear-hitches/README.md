# 恐惧击杀与召唤卡顿（2026-11-16，#219）

用户报告部分击杀和召唤幽魂时出现停顿。基线为PR #218的796a537，包含已修正牙齿的幽魂和爬坡怪；发布前并入最新main f8533be（仅审核文档/工作流变化，无玩法变化）。本次测量没有把此前的碰撞模板预热误当成新优化。

## 原因与处理

- 首次召唤临时创建3只完整幽魂演员、表情节点和材质。现在进房准备3只，4帧1%大小实际绘制准备完整张嘴管线；备用演员无逻辑/碰撞/增益注册。召唤只激活，空位每帧补1只。演员用后释放，避免状态/弱引用串到下一只。
- 最后击杀触发第一次馈赠读取。独立隔离测量中，`BoonCatalog.all()`单次219.133ms，最长帧220.789ms。现在恐惧房加载时读取并常驻定义，返回数组副本；资格与抽牌仍现场计算，未提前消耗抽牌随机数。
- 原有死亡仅缓存凸碰撞形状，仍在击杀帧创建56个刚体及其子节点。现在每个演员加载时预建树外节点，死亡才取当前骨骼姿态并启动真实碰撞；2.4秒后隐藏并每物理帧回收8块。未用的碎片随演员退出延后释放，避免信号回调内直接释放被锁对象。

## 原生壁钟测量

Godot4.7.2 / Vulkan Forward+ / RTX4060 Laptop GPU / 1280×720，关闭VSync、无帧率上限。玩家/敌人AI固定，保留真实生产房间、材质、物理与清场奖励。每个事件收集24帧，普通击杀40帧、Boss60帧；采样中无截图/图像回读。使用进程内首次事件，未清除驱动的持久着色器缓存，不代表全新设备冷缓存。

第一次召唤的同步CPU调用由33.847ms降至0.263/0.257ms；后两名普通敌人的同步死亡调用由1.225/1.298ms降至约0.63–0.65ms。首名普通敌人的死亡开销改善很小，仍约3.8–4.0ms CPU，不能据此声称所有击杀都加速数十倍。

基准默认直接进调试房，清场时首次创建选卡界面。额外`--entry`场景先展示并实际领取初始馈赠，最后击杀仍有36.466ms最长帧。拆分探针确认残余主要在Picker首次构建/卡片布局与绘制，约30ms同步构建；它会暂停战斗。本次没有消除这项UI开销，也不以本机数据承诺跨设备无卡顿。准备时间移到进房，常驻节点/资源有所增加，没有用减少碎片、简化幽魂或降低怪物数量换取测量结果。
